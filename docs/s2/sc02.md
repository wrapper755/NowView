## 규칙 (`app/s2/sc02/calc.py`)

* **A03 제안**(규칙 처리 — 실제 Agent 호출로 표시하지 않는다): U01 통합 점검 → U02 변경안 → U03 사람 확인 → U04 반영 →
  U05 재평가, 선행은 HAND-01 → 앞 항목. **Y01 검사**: 미등록 업무 · 필수 업무(U01·U05) · 생산계획을 바꾸면 U03 필수
  (`required_if_change`) · 선행 순서(누락·순환) · 위임 B(사람 확인 후 반영, U04)는 U03 뒤에만 · 위임 C는 이 사건에 없음. 하나라도
  어기면 `BLOCKED` — 변경안도 결재도 없이 끝나고 생산계획은 원본이다(T01). 위임 수준은 카탈로그 `UNIT_PLAN`(U01·U02·U05 A,
  U04 B, U03은 사람 확인)이다.
* **A02 변경안** — 장면 1 분석의 배정(입고분·사용 가능)을 그대로 쓴다(자재를 다시 배정하지 않는다). 착수 = max(자재 사용 가능,
  빈 라인 시작), 종료 = 착수 + 조립. 점검: 배정 = 확보 = 소요, 배정 입고분 = 확보 입고분, 빈 시간 종료 전 완료, 같은 라인의
  다른 주문과 겹치지 않음, 준비시간 있음. 하나라도 어기면 `confirmable: false`이고 **확정이 거절된다**(보완 요청만). 내용 식별값은
  기준 원계획 + 대상 행(수량·라인·입고분·착수·종료·준비)의 해시다.
* **확인** — H03만, 최신 판·같은 내용 식별값이어야 한다(409). 같은 판의 같은 결정이 다시 오면 기존 APP를 돌려준다(중복 클릭 —
  T03). 보완 요청이면 원계획 유지로 끝난다(T05). 확인 종류는 `production_plan_apply`이고 수행계획 적용과 다른 승인이다(F24).
* **반영** — 반영 직전에 확인 유효성과 **지금 원계획 버전**을 다시 본다. 바뀌었으면(다른 담당자가 고침) 반영하지 않고 그 확인을
  `EXPIRED`, 변경안을 `STALE`로 두고 그림이 새 판(PP-DRAFT-V2)을 써서 다시 확인받는다 — 이전 판·확인은 남는다(T04). 주문 한 행씩
  실행키 `{회차}:{확인 ID}:{약정}`으로 기간계 생산계획 저장소에 적는다(같은 키는 기간계가 다시 적지 않는다).
* **재조회 대조** — 기간계에서 **다시 읽은** 행을 승인본과 대조한다(저장 버전·확인 ID·수량·착수·종료·빈 시간 종료 안). 확인 ID가
  없으면 미반영, 있는데 값이 다르면 불일치. 응답 유실은 「결과 미확인」이고 실패가 아니다 — 재조회로 미반영이 확인된 주문만 같은
  실행키로 한 번 다시 보낸다(이미 일치한 S는 다시 적지 않는다, T07). 불일치 행은 보존하고 다시 반영하지 않는다.
* **재평가** — 재조회 일치 행만 쓴다(승인 초안이 아니다). 출하 준비 = 저장 종료 + 준비, 그 약정의 정기차 중 **마감 ≥ 준비**인
  첫 차(출발 순 — 같으면 탑승, T08), 여유 = 약정 − 예상 도착(분). 0 이상 인수 관찰, 음수 운송 확인. 대조 미완료·준비시간·정기차·
  도착 누락은 **보류**와 사유이고 0분으로 메우지 않는다. 다른 주문의 유효 결과는 그대로다.
* **인계(HAND-02)** — 운송 확인 주문만. 같은 판정 판이면 새 인계를 만들지 않는다(T09). 긴급차 확보·추가 운송비 전결·경영검토
  상신은 하지 않는다(`not_done`).
