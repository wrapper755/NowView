## 규칙 (`app/s2/sc04/calc.py`)

* **결과(N11)** — 약정마다 최신 판 증빙(판 번호 → 수신 순). 인수수량 = 약정수량이고 약정 − 인수 ≥ 0분이면 「정시 전량」, 수량·시각이
  없으면 「미확인」, 아니면 「미준수」. 정산이 없으면 비용 「미확인」 — 인수와 따로 판정한다. R은 결정 조건과도 대조한다(예약 < 예약 기한,
  정산 ≤ 결정 한도, 인수 ≤ 약정). 예약이 필요한 약정은 결정이 전량 긴급차(ALT-EXP)인 것이다. 증빙이 다 와야 개선 판단으로 간다.
* **초기선별(SNAP-0900)** — 그 시각까지 등록된 구매 개정(P-v2)과 원계획 PROD-V1, 장면 2 분석 사본으로 A02 변경안과 같은 규칙(자재
  가용·빈 라인 시작 중 늦은 시각 + 조립 + 준비)을 다시 낸다. 준비 ≤ 마감인 첫 정기차의 도착으로 여유 = 약정 − 도착. 배경은 「사건 범위
  밖」, 여유가 없으면 「보완」, 음수는 「조정 후보」. 승인(09:12)·반영본·회신은 입력이 아니다(미래 정보 점검 `uses_after_snapshot`).
* **요청** — 그 시각에 같은 주문의 운송 문의가 열려 있었으면 갱신, 아니면 재현 업무 한 건을 원업무 계보(W-TRAN-R)에 잇는다. 09:00에는
  W-TRAN-R(09:10 시작)이 없어 재현 업무다.
* **채택(구현명세 §3)** — 접수 ≤ 마감 · 수락 · 수용 ≥ 240 · 타 고객 차질 없음(0) · 추가운임 0 · 도착 ≤ 약정 · 출하 준비 ≤ 울산 출발 ·
  반영본 재조회 일치(장면 2 R)가 모두면 조정 정규편. 반영본 전(09:08)이면 「생산 반영 확인 대기」, 타 고객 영향이 미확인이면 「채택 보류 —
  근거 보완」, 그 밖은 「기존 운송 검토」(채택 ETA·비용 전망·회피액 공란, 도착 후보만). 회피 가능액 = 실제 정산 − 비용 전망(조건부).
* **시험(N14)** — 01~09는 구현명세 §4의 표를 그대로 판정한다(06 미확인·07 09:10 접수·반영 불일치·준비 지연은 기본 수락 분기를 그
  칸만 바꿔 다시 판정 — 시험 입력). 표본 = (조정 후보 수, 채택 수, 기존 운송 검토 수) = (1, 1, 7)이면 「표본 일치」. 미통과가 있으면
  H07이 「통과」로 적을 수 없다(422).
* **적용(N15·N16)** — H06 확인은 시험 통과가 있어야 하고 효력시점은 지금보다 뒤다(소급 422). H07 설정 버전은 확인한 버전이어야 한다.
  적용 상태 = 표본 일치 ∧ H06 확인 → 「신규 사건 적용」(아니면 「적용 보류」). 사건별 버전 = 사건 시각 ≥ 효력시점이면 KRI-CTL-v2,
  아니면 「기존 버전」(CASE-S2-01 — 장면 1 규칙 `KRI-S2-SUPPLY-v1`).
