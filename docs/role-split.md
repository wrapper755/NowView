# BPM 서버 · NowView · 회사 사이트 — 역할 분담과 전환 계획

2026-11-03 사용자 결정. NowView는 처음에 「BPM 프로세스 대시보드·데모」로 시작했지만 지금은 **서비스 태스크 일꾼 · 일꾼 ↔ 외부
서비스 연계 · BPM 프로세스 대시보드**다. 고객이 직접 보는 사이트가 아니라 BPM 관리 서버를 돕는 자리로 가고, **업무에 관한 것은 회사
사이트(Company1, `company1.nowview.work`)에서 BPM까지 포함해 다 보인다.** 경영 기록(분석 결과·이슈·업무·회의록·승인서 …)의 원본은
**회사 시스템(기간계)**이다 — 2026-10-31의 「규칙 계산·경영 기록은 NowView 몫」에서 **경영 기록**을 회사로 옮긴다(규칙 계산은 그대로
NowView다).

## 1. 세 서버가 하는 일

| 서버 | 쥐는 것 | 하지 않는 것 |
|---|---|---|
| **BPM 서버** (Chaeksas Center) | 업무 순서·결재·분기·실행 기록. 결재 담당 | 숫자·업무 규칙 |
| **NowView** (`www.nowview.work`) | ① 일꾼 — 서비스 태스크 수행, 규칙 계산(숫자는 규칙 계산만), Agent ② 외부 서비스 연계 — 회사 시스템 읽기·쓰기, Center 기동·메시지 ③ 대시보드 — N개 회사의 운영 현황(BPM 진행·일감·핵심 지표) ④ 관리자 | 직원 업무 화면, 결재 답, 경영 기록의 원본 |
| **회사 사이트** (Company1 `web`·`site-api`) | 사람이 하는 일 전부 — 직원 업무함·결재, 업무 판단 화면(현황·분석·비교·회의·승인서·인계), 회사 자료, 업무 설명, 시연 조작(자동 모드·원천 보내기·시계) | 업무 규칙·계산(기록을 읽어 보이기만 한다) |
| **회사 시스템** (Company1 `legacy`) | 회사 자료·확정 기록 + **경영 기록**, 세계(시연 회차)와 세계 시각 | 계산 |

```
 직원 ──▶ 회사 사이트 ──대리 답──▶ Center ──일감──▶ NowView 일꾼 ──규칙 계산──▶ 회사 시스템에 기록
             │                                                                    ▲
             └──────────────────────────── 기록·자료 읽기 ────────────────────────┘
 운영자 ──▶ NowView 대시보드 (여러 회사의 진행·일감·지표)
```

연결 방향은 그대로다 — NowView → Center, NowView → 회사 시스템, 회사 사이트 → Center, 회사 사이트 → 회사 시스템. **회사 사이트는
NowView를 부르지 않는다.** 업무 화면에 필요한 것은 전부 회사 시스템에 있어야 한다.

**의도적으로 남기는 중복**: NowView 엔진 문서는 일꾼의 **작업 상태**(BPM 진행·멱등·계산 입력)로 남는다. 경영 기록은 저장 직전에
회사에 적고 회사가 받지 못하면 그 조작을 저장하지 않으므로(지금 `_company_writes` → `_commit`과 같은 길) 둘이 갈라지지 않는다. 화면용
칸은 NowView 화면을 걷을 때(4단계) 줄인다.

## 3. 경영 기록 계약 (회사 시스템 — 1단계에서 만든다)

종류마다 고정 경로를 두면 장면 7개에서 40개가 넘는다. **봉투는 공통 계약, 본문은 종류별 스키마**로 둔다.

```
POST /worlds/{w}/records          {kind, record_id, version, scene, state, at, by, title, body, ref}
                                   ref 멱등(같은 ref·같은 내용 → 기존 줄, 다른 내용 → 409). 같은 record_id의 새 version은 앞 판을
                                   이력으로 남긴다(지우지 않는다). 지난 version이면 409
GET  /worlds/{w}/records?scene=&kind=&state=     → 각 기록의 최신 판
GET  /worlds/{w}/records/{kind}/{record_id}      → 최신 판 + history
POST /worlds/{w}/records/reset {scene}           (시연) 그 장면 기록만 처음으로
```

* **본문은 화면이 계산 없이 그릴 수 있는 모양**이다 — 비교 행·지표·판정·임계값·근거 id를 NowView가 계산해 싣는다. 회사 사이트는 단위만
  바꾼다(금액은 문자열 DECIMAL, 누락은 `null`). 사이트가 규칙을 다시 만들면 두 곳이 갈라진다.
* **본문 스키마의 주인은 NowView다** — 기록을 만드는 쪽이라서다. 종류별 JSON 스키마를 NowView 리포 `docs/records/`에 두고, 기간계는
  봉투만 검사한다. 대신 시험 두 벌이 계약을 잠근다: NowView 엔진 시험이 적는 본문을 스키마로 검사하고, Company1 사이트 시험이 같은
  스키마의 예시로 화면 읽기를 검사한다.
* 장면 1 종류(파일럿, `engine/app/sc01/records.py`): `scene`(머리 — 시연 시각·장면 상태·실행 위치·판정 임계값 R01·알림·회사와 오간 것),
  `source`(받은 원천 사본·자동 검증·확인 결정), `forecast`(F02 검토 전망), `calc_run`(비교 계산 — 모델·월별 지표·위험 판정),
  `issue`(관심/중요·열림·이력), `task`(담당·기한·인수·재확인·기한 초과), `review`(담당자 검토 의견), `agent_draft`(AI 초안 — 검증 통과한
  응답만, 입력 원문·거절 응답 없음), `handoff`(완료 조건·정정 이력·감사 이력), `dashboard`(UI01 — 기간 17개·월 7~9월을 미리 계산, 목표
  부족액·사건 영향까지). 처음 적은 일곱 종류에 화면이 실제로 읽는 셋(`scene`·`source`·`review`)을 더했다. 원천 확인 결정은 그대로
  `customer-plans/{doc}/status`에도 적는다.
* **본문은 NowView 장면 1 화면이 읽는 모양 그대로다**(2026-11-03 사용자 결정 — 나란히 대조하기 쉽고 다른 장면도 같은 방식). 화면이 하던
  뺄셈(목표 부족액 T − 최신, 사건 영향 최신 − F01)은 `dashboard.gaps`로 옮겼다 — 회사 사이트는 빼지 않는다.
* **바뀐 기록만 새 판으로 적는다** — 엔진 문서의 `company_records`에 기록마다 (판, 본문 해시). 기본 시연 한 바퀴에 기록 16개·판 합계 89다
  (`scene`·`handoff`는 감사 이력이 늘 때마다, `dashboard`는 시계가 갈 때마다 판이 오른다).

## 4. 단계

1. **장면 1 파일럿 — 끝**(2026-11-03). 기간계 경영 기록 계약(+ NowView 시험 쌍둥이 `company_twin`), NowView 장면 1이 저장 직전에
   기록을 적는다(`Sc01Process._write_records` — `_commit`·생성·Agent 초안 저장, 회사가 받지 못하면 저장하지 않는다), 회사 사이트에
   장면 1 업무 화면 다섯(`/work/{회차}/sc01` — 현황·고객계획·위험 검토·업무·인계)을 기간계 기록만으로 그린다. NowView 장면 1 화면은
   그대로 뒀다. **로컬 Center 실측**: `demo-293180f5`를 각본으로 인계까지(결재 한 단계 10~22초, BPM `done`) — 기간계 기록 16개의 본문이
   엔진 화면 응답과 칸 단위로 같다(원천·계산·이슈·업무·검토·인계 조건·대시보드 Q3), 두 화면을 나란히 열어 숫자(33.09억 · 목표 대비
   −1.68억 · 사건 영향 −1,400만 · b모델 7월 7.37% · 1,400만원 · 12% · 중요)·업무 다섯·완료 조건 넷이 같은 것을 봤다. 남은 것:
   * 사이트는 회차 단위 지난 시점 보기(되감기)가 없다 — 기록의 지난 판(history)은 있지만 화면은 최신 판만 그린다.
   * 회사 사이트 web의 `npm run build`는 돌리지 않았다(dev가 3100에서 돌고 있어 — `tsc --noEmit`·lint만).
   * 결재는 여전히 직원 화면(`/employees/…`)에서 한다 — 업무 화면의 업무 줄에서 그 결재로 잇는 링크는 2단계에서.
2. **시연 조작을 회사 사이트로** — 원천 도착(사이트가 기간계에 원천을 보내면 NowView가 수신함을 읽어 Center를 깨운다), 세계 시각의 원본을
   기간계로, 자동 모드(각본), 명단을 기간계에서 읽기, NowView 화면 답·플레이어를 걷는다.
3. **장면 2~7** — 장면마다 기록 종류 정의 → NowView가 적기 → 회사 사이트 업무 화면.
4. **NowView 정리** — 장면 화면을 걷고 대시보드(회사·업무별 BPM 진행·일감·핵심 지표)와 관리자만 남긴다. 해설·업무 설명은 회사 사이트로,
   엔진 문서의 화면용 칸을 줄인다.
5. **운영** — `company1.nowview.work` 배포(사이트 비밀번호 하나), 운영 Center 연결(CLAUDE.md 5.4).

각 단계 끝에 로컬 Center로 그 장면을 끝까지 돌려(회사 사이트 답과 자동 모드를 섞어) 기록·시각이 지금 NowView 실행과 같은지 대조한다.
