# 시나리오 3 장면 1 — 결산조정 업무 착수 (업무설계표 01~06)

2026-11-06. 기준 문서(리포 밖, Downloads/시나리오3/장면1): 구현명세 v0.1 · 상세화면 구성·시연 순서 v0.1 · 업무설계표 v0.1. 공통 설계는
`docs/s3/common.md`, 입력은 `engine/seed/S3-INPUT-v0.1.xlsx`(입력자료 명세 및 대표 사건 v0.1).

> 회계담당자가 배정된 감가상각비와 외상매출금 대손충당금의 입력자료를 점검한다. 두 항목이 각각 분석 준비 완료가 되고, 대손충당금
> 행에 [분석 지시 보기]가 보이면 정상 시연이 끝난다.

## 숫자 (입력 IN-26-01 — `engine/tests/test_s3_sc01.py`가 점검 결과로 다시 낸다)

| 항목 | 정상 표본 |
|---|---|
| 감가상각비 | 자산 8건 · 신규 E2 사용개시일 2026-07-01 · 원장 당기 기계상액 1,150백만원 |
| 채권명세·원장 대사 | 당기 7행 합계 6,458.799691백만원 = 원장 외상매출금 · 차이 0원 |
| 조정 전 충당금 | 전기말 100 − 당기 제각 20 = 80백만원 |
| 전이율원천 | 일반거래처 7개 구간 × 16분기(2021.1Q~2024.4Q) · 원 단위 |
| A사 | 당기 계획 PLAN-A-26 3회 × 20 = 60 · 영업 확인 CONF-26-S · 회계 평가 CONF-26-F 60 (전기 PLAN-A-25는 따로) |
| 끝 | 분석 준비 2/2 · 보완 0 · 승인 0/2 · 상신 0건 · 인계 HAND-S3-01 |

## 흐름

```
사이트가 시나리오 3 회차를 만든다(기간계: 입력 IN-26-01 연결·두 항목 배정 — 선행 업무 끝) ─▶ NowView 세계 따라가기
   ─POST /jobs─▶ Center(company1.s3.sc01) — 결산 건 하나 = 실행 하나
Task_Link(자료 연결 확인 03) → Task_Route(다음 점검 항목) ─┬ DEP ▶ Check_Depreciation(회계담당 「점검 실행」) → Record(04 점검) ─┐
                                                          ├ ALW ▶ Check_Allowance(회계담당) → Record(05 점검) ──────────────┤
                                                          ├ WAIT ▶ Wait_Fix(메시지 「결산자료보완」) → Task_Link ──────────┤
                                                          └ DONE ▶ Task_Handoff(06 장면 2 인계) → End          ◀── Task_Route ┘
   서비스 태스크는 C15 일꾼(`app/s3/sc01/process.py` run_operation) → 경영 기록을 기간계에 적는다
```

* **업무 번호 31**(`docs/platform.md` §7). 설정 매핑 `company1.s3.sc01 → 31`, 패키지 `CHAEKSAS_S3_SC01_PACKAGE`. 확장 `external`
  0.13.0이 작업 넷(`link_close_inputs`·`route_close_items`·`check_close_item`·`hand_off_close_items`)을 더했다.
* **어느 항목을 점검할 차례인지는 규칙이 고른다**(`route`) — 지금 입력으로 점검하지 않은 항목(감가상각비 먼저), 없고 둘 다 준비
  완료면 인계, 보완 필요만 남으면 보완 대기. 보완을 기다리는 항목이 다른 항목의 점검을 막지 않는다(인수시험 03).
* **점검은 회계담당자의 결재 답이다**(폼: 본 입력 버전 + 「점검 실행」). 사이트가 대리 답한다. 결재지만 승인이 아니다 —
  체크리스트의 승인 0/2·상신 0건은 그대로다. 열람·팀장 조회는 그림에 없다.
* **본 입력 버전이 최신이 아니면 409** — 기록이 거절되어 같은 점검으로 돌아간다. 옛 점검 응답의 재전송이 새 자료 상태를 덮지
  않는다(인수시험 07). 같은 버전·같은 입력의 점검을 다시 보내면 기존 결과다. 배정 담당이 아닌 사람의 답은 403 → 같은 점검(08).
* **자료 보완** — 자료 담당자가 입력을 다시 연결하면(기간계 `sim/close-inputs`) 세계 따라가기가 `receive_inputs`로 넘긴다.
  그 항목이 쓰는 칸의 지문이 바뀐 항목만 「재점검 필요」다(원장은 행 단위 — 자산자료 교체가 충당금을 흔들지 않는다). 실행이
  보완을 기다리면 메시지로 깨우고(`no_receiver`면 폴러가 다시), **이미 인계했으면 인계를 무효로 하고 재점검 실행을 새로
  기동한다**(앞 실행은 `bpm_history`). 장면 2 진입도 서버가 준비·권한·최신 버전을 다시 확인해야 한다(인계의 `valid`).
* Center 멱등 키 `s3sc01:{회차}:e{center_epoch}` — 재점검 실행마다 `center_epoch`를 새로 짓는다.

## 규칙 (구현명세 §1·§2 · `app/s3/sc01/calc.py`)

| 점검 | 무엇을 | 보완 담당 |
|---|---|---|
| C-01 | 입력 시트 = 허용 7개 | 회계 |
| C-02 | 기준일 2026-12-31 · 비교 2025-12-31 | 회계 |
| C-03 | 그 항목이 쓰는 시트의 단위(전이율원천만 원 — 충당금만 쓰므로 그 오류는 감가상각비를 막지 않는다) | 회계 |
| DEP-01~05 | 자산 ID 유일 · 자산별 필수값(종류·귀속·원가·잔존가·양의 연수·개시일·전기 상각 …) · 처분일 ↔ 처분 순액 · 신규 자산 개시일이 당기 · 원장 당기 기계상액 1행 | 자산담당(05는 회계) |
| ALW-01~02 | 당·전기 명세 · 집합/개별 배타·개별은 계획 참조 | 채권담당 |
| ALW-03 | 당기 명세 합계 = 원장 외상매출금 — **원 단위 정수로** | 채권담당 |
| ALW-04 | 전기말 충당금 − 당기 제각 = 조정 전 잔액 | 회계 |
| ALW-05 | 전이율원천 16분기·빈 칸 없음·원 단위 정수 | 회계 |
| ALW-06 | 당기 계획(채권명세 개별 행이 가리키는 것) — 회차 중복·기준일 다른 행이 있으면 **합산하지 않는다** | 영업 |
| ALW-07 | 영업의 당기 회신 확인 1건 · 같은 계획 버전 | 영업 |
| ALW-08 | 회계의 기준일 평가 기록 1건 · 같은 계획 버전 · 확인액 = 회차 합계 | 회계 |

* 모든 필수 점검이 통과해야 준비 완료다. 공란은 0이 아니고 추정액으로 채우지 않는다. 보완 요청은 실패한 점검마다 대상 시트·행(근거
  ID)·기대값·확인값·담당 역할을 남기고, 기한은 다음 영업일 18:00(가안)이다. 다음 점검이 통과하면 그 요청은 해소, 다시 실패하면 대체다.
* 기한·잔여일은 결산 일정(기간계 master — 가안: 착수 2027-01-04 09:00, 상신 기한 1/8 18:00, 승인 1/11, 전표·주석 1/13)에서 읽는다.
  기한 경과와 자료 보완은 따로 표시한다.

## 남은 것

* **Center에 올릴 것(사람이 한다)**: 확장 `external` 0.13.0은 일꾼이 뜰 때 올린다. Studio에서 `company1.s3.sc01`(Company1
  `bpm/company1/company1.s3.sc01`)을 내보내 승인·배포. 저장된 설정이 있는 엔진 DB에는 관리자 모드로 `company1.s3.sc01 → 31`을 더한다.
  기간계에 새 사용자(회계팀장·회계담당·자산담당·채권담당·자료담당)가 있어 기간계를 다시 띄워야 사이트 직원 목록에 보인다.
* 로컬 Center 실측은 아직이다(엔진 시험은 진짜 BPM 엔진 + C15 수행기로 끝까지 갔다).
* 결산 일정·보완 기한은 가안이다(자료에 없다). 체크리스트의 「다른 결산조정항목」은 표본 둘뿐이다.
* 장면 2(프롬프트 실행·연계 PC Excel 첨부)는 `docs/s3/sc02.md`, 장면 3(승인·후속 인계)은 `docs/s3/sc03.md`다.
