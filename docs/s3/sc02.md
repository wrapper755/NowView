## 실행 기록과 실행 방식 (`docs/s3/common.md` §5에서 정한 것)

| 기록 | 저장하는 값 |
|---|---|
| 실행 접수 `analysis_run` RUN-S3-nn | 결산 건·두 원업무(W-S3-DEP·W-S3-ALW)·실행자·요청 시각·입력 버전·지문, 버전 묶음(프롬프트 `PRM-S3-SC02-v0.1` · 서식 `FMT-S3-WP-v0.1` · 계산 기능 `S3-SC02-CALC-v0.1` · Agent `AGT-S3-CLOSE-v0.1(규칙 문안)` · 실행 환경 `ENV-S3-PC-SIM-v0.1`), 정책(결산기준 = 입력 버전), **`execution_mode`·`execution_note`** |
| 작업 단계 | 접수 → PC 수신 → 계산 중 → 계산·대사 완료 → 파일 생성 → BPM 첨부 등록 → 열기 확인 → 검토 대기. 단계마다 상태(대기·처리 중·완료·보완·실패)·세계 시각·실제 응답 시각, 마지막 성공 단계·마지막 응답 시각, 상태 조회 횟수 |
| 대사 | 명세·원장 차이(원), 최대 차이, 당·전기 집합·개별 고유 거래처 수, A사 계획·확인 일치 |
| 결과 `close_result` RES-S3-vN | 두 항목 계산 전부(아래 규칙)·승인 요약 행·보완 대상·Agent 문안(수치마다 결과 칸 참조) |
| 첨부 `attachment` WP-S3-vN | 파일 id·버전·실행·결과 버전·이름·지문(sha256)·크기·시트·서식 버전·승인요약 칸 위치·추적 경로·전송 시도·열기 확인 |

* **`execution_mode: simulated` — 이번 판은 모의 실행이다.** 연계 데스크톱 PC·Excel 연동이 없다. NowView 일꾼이 같은 계산과 같은
  시트·수식 구성의 `.xlsx`를 만들어 결산 건(기간계)에 첨부한다. 실행 기록·Excel의 `실행정보` 시트·사이트 화면이 이것을 드러낸다.
  파트너의 구현 가능 확인과 실제 연동 시험 결과는 따로 남긴다 — 실제 PC 연계를 붙이면 그 실행은 `execution_mode: pc`다(남은 것).
* **PC 미응답·전송 실패는 지어내지 않는다** — 시연자가 기간계 스위치(`sim/close-faults` — `pc_delay`·`transfer_fail`)를 켠 횟수만큼만
  난다. 화면은 경과 시간으로 상태를 재생하지 않고 작업의 응답으로만 바뀐다.
* **첨부 대기** — 계산이 끝났는데 전송이 실패하면 실행은 `ATTACH_WAIT`, 파일은 `TRANSFER_FAILED`로 남고 회계담당자의 [첨부 재시도]가
  같은 실행·같은 파일을 다시 보낸다(새 파일을 만들지 않는다 — 같은 결과·실행이면 같은 바이트다). 등록한 파일을 기간계에서 다시 읽어
  열리는지 확인한 뒤에만 검토 대기다(인수시험 06).
* **재실행은 파일 버전과 이력을 구분한다** — 입력이 바뀌면 새 실행(RUN-S3-02)·새 결과(RES-S3-v2)·새 파일(WP-S3-v2)이고 앞 실행은
  `SUPERSEDED`로 남는다. 이전 실행의 응답은 최신 결과를 덮지 않는다(409).
* 연속 클릭 — 같은 입력의 실행이 있으면 그 실행이다(실행 1건). 같은 입력으로 보완 필요가 난 실행은 다시 돌리지 않는다(409 — 자료 보완이 먼저).

| 항목 | 규칙 |

| 전이율 | 시작 분기 구간 잔액 대비 다음 분기 다음 구간 잔액, 상한 1, 분모 0 미산출. 가중 = Σ min(시작, 다음) ÷ Σ 시작(최근 12개 관측). 단순평균은 비교용 |
| 누적 PD · 설정률 | 그 구간부터 9~12개월까지 가중 전이율의 곱 × 12개월 초과 PD 100%, LGD 100%. 원천 12~15개월·15개월 초과는 12개월 초과로 합산. 2024년 모형을 두 기간에 고정 |
| 집합평가 | 일반거래처 평가행 × 설정률, 행마다 원 단위(백만원 소수 6자리) 반올림 후 합산 |
| 개별평가 | 채권 − 회계 평가 기록(그 기준일·그 계획 버전)의 확인액. 계획 회차 합계와 같아야 하고 당기는 영업 확인도 같은 버전 — 아니면 계산하지 않고 보완 대상(공란을 0·추정액으로 채우지 않는다) |
| 충당금 요청액 | 기말 필요액 − 조정 전 잔액(전기말 − 당기 제각). 양수면 추가 설정, 음수면 환입. 주석 = 기초 + 설정 − 환입 − 제각 = 기말 |
| 감가상각비 | (취득원가 − 잔존가) ÷ 내용연수 × 당기 사용월수 ÷ 12, 상각 가능 잔액(기초 + 취득 − 처분 − 손상 − 잔존가) 한도. 개시월 포함·처분월 제외·내용연수 끝난 달부터 0. 전기는 자산대장 확정값 |
| 감가상각 요청액 | 당기 계산액 − 원장 기계상액 |
| 대사 | 명세 합계 = 원장 외상매출금, 조정 전 = 기초 − 제각, 주석 충당금 = 평가표, 자산 종류 합계 = 비용 귀속 합계 = 주석 상각, 기말 순액 롤포워드 — 모두 원 단위 정수 |

* **Agent 문안은 규칙 문안이다**(`calc.draft`, `mode: rule-template`) — 결과 칸을 정해진 문장에 이어 붙인다(LLM 호출 없음). 수치마다
  결과 칸(`depreciation.summary.request` …)을 가리키고, 팀장 판단을 지시하는 문구를 넣지 않는다.

## 첨부 Excel (`app/s3/sc02/workpaper.py`, 서식 FMT-S3-WP-v0.1)

견본 v0.1의 12개 시트(승인요약·상각비비교·유형자산주석·충당금비교·충당금주석·자산별계산·채권별계산·개별평가·손실률·분기전이율·
참고원천·원장대사) + `실행정보`. 원천 수치는 값, **금액·비율은 수식**이다 — 승인요약의 요청액(`=C5-E5`)이 상각비비교·충당금비교·
원장대사를 거쳐 자산별계산·채권별계산·손실률·참고원천까지 이어진다. 사용월수만 계산 기능이 낸 값이다. openpyxl은 계산값을 저장하지
않으므로 여는 프로그램이 다시 계산한다 — LibreOffice로 다시 계산하면 수식 오류 0, 대사 차이 0, 승인요약 = 화면 요약(인수시험 07,
`soffice`가 있으면 시험이 돈다). 같은 결과·실행이면 같은 바이트다(압축 시각·문서 속성 시각을 실행 시각으로 고정).

## 검토와 상신

* **검토는 항목마다 결과 버전에 묶인다**(`item_review` REV-{항목}-n) — 배정 담당만, 본 결과 버전이 최신·유효하고 첨부가 등록·열기
  확인됐을 때만. 첨부 열람 이력(기간계 `close-attachments/{id}/opens` — 사이트의 [첨부 Excel 열기])과 검토 완료는 따로 남는다.
* **입력이 바뀌면**(세계 따라가기가 장면 1에 이어 장면 2에도 넘긴다) 지금 결과는 낡음(`stale`) — 체크리스트 「재계산 필요」, 검토·상신
  409 → 다시 고르기가 RERUN으로 실행 요청에 돌아간다. 장면 1 재점검·재인계 뒤 다시 실행하면, **입력 지문과 요청 금액이 같은 항목의
  검토는 승계**(`CARRIED`, `carried_from`)하고 바뀐 항목만 다시 검토한다(인수시험 08 — E2 가동 8월 정정: 상각비 1,183.333333 · 요청
  33.333333, 충당금 검토 승계).
* **상신은 한 번이다**(`close_report` REP-S3-01 v1) — 두 검토 완료 · 대사 차이 0 · 최신 입력 · 결과 버전 일치 · 첨부 열기 가능 · 담당
  권한. 두 항목 요청액·변동 사유(문안)·주석 발췌·첨부(파일 id·버전·지문)·실행·검토자·수신 회계팀장을 하나로 고정하고 장면 3 인계
  HAND-S3-02를 남긴다. 같은 상신의 재전송은 같은 보고 ID. 상신 뒤의 변경은 장면 3 팀장 보완 요청의 몫이다(409).

## 남은 것

* **Center에 올릴 것(사람이 한다)**: 확장 `external` 0.14.0은 일꾼이 뜰 때 올린다. Studio에서 `company1.s3.sc02`(Company1
  `bpm/company1/company1.s3.sc02`)를 내보내 승인·배포. 저장된 설정이 있는 엔진 DB에는 관리자 모드로 `company1.s3.sc02 → 32`를 더한다.
* 로컬 Center 실측은 아직이다(엔진 시험은 진짜 BPM 엔진 + C15 수행기로 끝까지 갔다).
* **실제 연계 PC·Excel** — 파트너의 실제 연동 시험 전이다. 붙이면 `process_close_analysis`·`attach_close_workpaper`가 PC 응답을
  받아 같은 단계를 남기고 `execution_mode: pc`로 적는다. 「이 업무의 Agent 설정」 조회(관리자 등록 구성)도 아직 없다 — 버전 묶음은 실행
  기록에만 있다.
* 담당자의 문안 수정(수정자·버전)과 검토의 「보완 필요」 선택지는 없다 — 금액·근거 수정은 입력 보완 → 재실행 길뿐이다.
* 장면 3(팀장 승인·보완 요청·전표 반영·주석 취합 인계)은 HAND-S3-02에서 시작한다(`docs/s3/sc03.md`). 상신 뒤 보완 요청의 재계산·재검토·
  재상신은 장면 3이 장면 2와 같은 계산 기능으로 한다 — 장면 2 문서(상신본)는 그대로다.
