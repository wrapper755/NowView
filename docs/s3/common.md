## 2. 세 서버 위의 자리

| 무엇 | 자리 | 이유 |
|---|---|---|
| 결산 건·조정항목 배정·결산 일정·입력 원천(7개 시트)·입력 버전 | 회사 시스템(기간계 `s3.py`) | 회사의 자료와 업무 배정이다. NowView는 읽기만 한다 |
| 흐름(점검 순서·보완 대기·인계, 장면 2·3의 상신·승인) | BPM Center(`company1.s3.sc0N`) | 결정론적 흐름은 BPM이 쥔다 |
| 준비 판정·대사·보완 대상(장면 1), 계산·전기 비교(장면 2) | NowView 규칙 계산(`app/s3/sc0N/calc.py`) | **숫자와 판정은 규칙 계산만 만든다**(AG-01). Agent는 설명·주석 문안 |
| 결산 체크리스트·점검 화면·승인 요약 | 회사 사이트(`/work/{회차}/s3/sc0N`) | 사람이 하는 업무 화면이다. 체크리스트의 행 선택이 원업무로 간다 |
| 체크리스트 집계 지표 | NowView 회사 대시보드(`/c/company1`, 업무 31) | 승인 버튼 없는 읽기. 숫자는 경영 기록에서 고르기만 한다 |

* **체크리스트는 대시보드이자 업무의 문이다**(BPM v0.2 「결산조정사항 체크리스트 대시보드」). 행을 고르면 원업무로 가므로 업무
  화면 쪽(회사 사이트)에 두고, NowView 대시보드에는 집계(준비·보완·승인·상신)와 사이트 링크만 둔다.
* 팀장의 조회와 담당자의 업무 열람은 **결재 기록을 만들지 않는다**. 담당자의 점검은 원업무의 할 일(Center 결재 — 사이트가 대리
  답)이지 승인이 아니다. 「승인」은 장면 3의 팀장 승인 하나다.

## 3. 공통 대상과 경영 기록

| 대상 | 키 | 원본 | 기록 종류(`docs/records/s3/`) |
|---|---|---|---|
| 결산 건 | `S3-CLOSE-01` | 기간계 master(기간·비교기간·검토자·일정) | `close_case` — 연결된 입력 버전 이력 포함 |
| 조정항목(체크리스트 한 행) | 원업무 id `W-S3-DEP`·`W-S3-ALW` | 기간계 배정(담당·시트) | `close_item` — 단계·기한·잔여일·보완·다음 조치·승인·상신·후속 |
| 입력 버전 | `IN-26-01` … | 기간계 `close-inputs`(시트 7개·단위·추출 참조·지문) | `close_case.inputs` |
| 입력 점검(장면 1) | `CHK-{항목}-{n}` | NowView 규칙 | `input_check` |
| 보완 요청 | `FIX-S3-{nn}` | NowView 규칙 | `fix_request` |
| 장면 인계 | `HAND-S3-01` | NowView | `handoff` |
| 체크리스트 집계 | `S3-CLOSE-01` | NowView | `dashboard` |
| 분석 실행·첨부 Excel·보고 건·승인(장면 2·3) | 실행 id·파일 버전·보고 버전 | (장면 2·3에서 정한다) | — |

* **한 행 = 결산기간별 조정항목 한 건**. 분모는 지금 조회 범위의 대상 항목 수이고, 상신은 **고유 보고 건 수**로 센다. 전표 반영·
  주석 취합은 항목마다 따로 센다(표본 승인 직후 승인 2/2 · 보고 1건 · 전표 0/2 · 주석 0/2). **준비 완료는 결산마감 완료가 아니다.**
* **입력 버전은 지문으로 본다** — 자료 담당자가 다시 연결하면 새 버전이고, 항목이 쓰는 칸(원장은 행 단위)의 지문이 바뀐 항목만
  재점검 대상이다. 이전 점검 결과·시각은 이력으로 남는다. 같은 버전 id가 「장면 1부터 다시」 뒤에 다른 내용일 수 있어 캐시는
  내용 지문(`digest`)으로 한다.
* **입력 허용목록**: 결산기준·자산대장·채권명세·전이율원천·원장·회수계획·확인기록 7개. 설계안내·입력명세·대표사건·검수기준은
  설계·기대값 대조용이라 기간계가 싣지 않고 Agent 입력에서도 뺀다.
* 단위: 전이율원천만 원, 그 외 금액은 백만원. 원 단위(백만원 소수 6자리)로 비교한다 — 표시 반올림 전 차이를 잡는다.
* 화면·Excel·주석 발췌표에는 **같은 보고 버전**을 붙인다(장면 2·3). 승인 요청액(조정액)과 전기 대비 증감은 다른 숫자다 —
  감가상각비는 당기 계산액 − 기계상액(1,200 − 1,150 = 50), 대손충당금은 기말 필요액 − 조정 전 잔액(110 − 80 = 30). 전기 대비
  +80·+10과 섞지 않는다.

| 전표 반영 · 주석 취합 담당자 | (장면 3에서 정한다) | 승인 뒤 후속 업무 |
| 결산분석 Agent | (장면 2) | 계산 기능 호출 결과로 전기 비교·변동 설명·주석 표 작성 |

그 이름이다.

## 5. 장면 2 실행 환경 — 남겨 둔 자리

개발 파트너가 「BPM에서 Agent를 불러 계산 자료를 만들고 결산 건에 연결」하는 방식이 가능하다고 확인했다. 실행 방식은 둘이다 —
① 서버 봇 + Google Sheets, ② **데스크톱 PC + Excel**(BPM 실행 요청을 연계 PC에 넘겨 Excel로 계산 시트를 만들고 `.xlsx`를 결산
건에 첨부 — 합의된 Excel 첨부 시연의 기본안). 장면 1은 이것을 쓰지 않는다. 장면 2에서 정할 것:

* 실행 기록(M22)에 결산 건·실행자·자료·프롬프트 버전·산출물·처리 결과를 함께 남긴다. **파트너의 구현 가능 확인과 실제 연동 시험
  결과는 따로 기록한다**(`execution_mode` — 실제 PC 연계·모의·재현을 구분, 공통 플랫폼 F05).
* 계산이 끝났는데 첨부가 실패하면 「첨부 대기」로 두고 같은 실행 건에서 재시도한다. 담당자가 검토할 수 있을 때만 검토 대기로 바꾼다.
* 재실행은 파일 버전과 이력을 구분한다. 승인 요약의 금액과 첨부 계산 행이 같아야 한다(견본 v0.1이 기대값).
* 「이 업무의 Agent 설정」(관리자가 등록·변경 — 입력자료·계산 기능·실행 환경·프롬프트·출력 서식 버전)은 NowView 관리자 쪽이다
  (공통 플랫폼 UI-A).

측정하지 않는다(지어내지 않는다).
